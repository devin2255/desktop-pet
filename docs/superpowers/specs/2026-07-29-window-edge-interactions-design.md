# Windows 桌宠窗口边缘互动设计

## 目标

为通用 Windows 桌宠播放器增加可复用的窗口边缘互动系统，同时修复人物可见边界和文字气泡在不同尺寸下的定位问题。

本次交付针对 `son-pet` 生成配套真人动作素材，但播放器能力不得包含人物名称、身份特征或素材路径。其他 `.petpack` 可通过相同清单字段复用该能力。

## 已确认的产品规则

### 拖动

- 鼠标开始有效拖动后，宠物立即切换为资源包配置的爬行姿态。
- 静止点击继续视为互动，不得触发拖动。
- 拖动期间停止随机漫游和其他互动计时器。
- 人物的可见像素允许真正到达屏幕物理边缘；透明画布边距不得阻挡拖动。

### 目标窗口选择

- 松手时选择鼠标位置下方、从前到后排列的第一个普通可见窗口。
- 排除桌宠自身、桌面、任务栏、隐藏窗口、最小化窗口和无效尺寸窗口。
- 窗口命中优先于屏幕顶边坠落判定。
- 探测失败时退化为普通拖动，不影响播放器启动或退出。

### 窗口边缘行为

- 所有坐标先统一为 Electron 使用的设备无关像素（DIP）；窗口探测返回原生像素时，按目标显示器 `scaleFactor` 转换。
- 边缘激活区为距离窗口外框 32 DIP 以内。
- 同时命中多个边缘时优先级为：顶部、下边缘、侧边。
- 窗口顶边：直接进入坐窗姿态。
- 窗口左/右侧：播放攀爬动画，自动移动到窗口顶边，然后进入坐窗姿态。
- 窗口下边缘：进入双手抓住下边缘的悬挂姿态。
- 指针位于窗口中央且距离所有边缘超过 32 DIP 时不附着，按普通拖动结束。
- 再次拖动宠物时解除窗口附着，切回爬行拖动态。

### 附着生命周期

- 保存目标窗口 ID、附着边缘和相对偏移。
- 附着期间以约 100ms 间隔检查目标窗口。
- 窗口移动时宠物跟随。
- 窗口最小化、关闭或句柄失效时，宠物进入坠落恢复流程。
- 附着、攀爬、坠落和恢复期间禁止随机漫游。

### 屏幕顶部坠落

- 仅在松手位置没有有效目标窗口、且人物可见顶部到达当前显示器物理顶边时触发。
- “到达顶边”定义为人物可见顶部距离显示器顶边不超过 6 DIP。
- 动作顺序为：坠落、落地摔坐、起身拍屁股、恢复正面跪姿。
- 完成后回到宠物当前所在显示器的右下角默认位置。
- 多显示器的屏幕边界、工作区和落点都以宠物当前显示器为准。

## 技术架构

### 窗口探测层

新增独立窗口探测模块，通过 `get-windows` 的 `openWindows()` 获取按前后层级排列的窗口、边界、窗口 ID 和所属进程。模块使用依赖注入向纯逻辑层提供窗口列表，便于测试和安全降级。

探测层职责：

- 动态加载平台模块；
- 获取鼠标位置下方的候选窗口；
- 排除桌宠进程和系统壳窗口；
- 返回稳定窗口 ID 和边界；
- 在非 Windows 平台或加载失败时返回“功能不可用”，不抛出致命错误。

依赖文档：https://www.npmjs.com/package/get-windows

### 互动状态控制器

主进程维护一个互斥状态机：

```text
normal
  -> dragging
      -> normal
      -> climbing -> perched
      -> perched
      -> hanging
      -> falling -> impact -> recovering -> normal

perched / hanging
  -> dragging
  -> falling -> impact -> recovering -> normal
```

控制器职责：

- 中止和恢复行为计时器；
- 决定松手后的目标状态；
- 根据目标窗口变化更新宠物位置；
- 使用约 16ms 的物理计时更新坠落位置；
- 播放完成后恢复当前显示器右下角；
- 保证所有窗口尺寸更新使用绝对尺寸，防止连续动作缩放漂移。

坠落使用恒定加速度模型，初始速度为 0、加速度为 1800 DIP/s²，单帧最大位移限制为 48 DIP，防止调度暂停后穿过落点。`impact` 与 `recover` 的持续时间使用资源包动画时长总和，不在播放器中写死人物动作时长。

### 纯逻辑模块

窗口选择、边缘分类、可见范围限制、附着位置计算和坠落轨迹使用无 Electron 依赖的纯函数实现。

建议接口：

```text
selectTargetWindow(pointer, windows, exclusions)
classifyWindowEdge(pointer, windowBounds, thresholds)
clampByVisibleBounds(windowBounds, visibleInsets, displayBounds)
positionForAttachment(windowBounds, anchor, mode, petSize)
nextFallFrame(current, elapsed, displayBounds)
```

### 可见像素边界

渲染进程在每帧图片加载后从 alpha 通道计算人物可见包围盒，并换算为当前窗口内的像素边距：

```text
visibleInsets = { left, top, right, bottom }
```

可见范围通过受信 IPC 发送给主进程。主进程使用它处理：

- 屏幕边界限制；
- 顶边坠落阈值；
- 窗口边缘对齐；
- 多显示器切换；
- 当前动作帧变化造成的少量边界差异。

透明上边距可以移出屏幕，但人物可见区域必须保留在所选显示器允许范围内。

### 动态气泡

气泡不再使用固定 `top` 像素值。渲染进程根据当前图片的实际显示矩形和 alpha 顶部定位气泡：

- 默认位于人物可见头顶上方 6px；
- 保留 4–8px 的可接受视觉间距；
- 必须限制在窗口可显示区域内；
- 小、中、大三个尺寸使用相同计算；
- 动画帧切换时不得明显抖动，可对连续位置应用小范围平滑或使用当前动作可见顶部的稳定统计值。

## 资源包扩展

### `interactionActions`

`pet.json` 增加可选通用字段，由资源包把逻辑互动状态映射到动画：

```json
{
  "interactionActions": {
    "drag": { "action": "walk" },
    "climb": { "action": "climb", "anchor": { "x": 0.5, "y": 0.5 } },
    "perch": { "action": "perch", "anchor": { "x": 0.5, "y": 0.7 } },
    "hang": { "action": "hang", "anchor": { "x": 0.5, "y": 0.1 } },
    "fall": { "action": "fall" },
    "impact": { "action": "impact" },
    "recover": { "action": "pat-butt" }
  }
}
```

锚点坐标相对于统一动画画布，范围为 `0..1`。校验器必须确认动作存在、坐标有限且位于有效范围内。

缺少字段或个别动作时使用安全回退：

- `drag` / `climb` 回退到 `walk`；
- `perch` / `hang` 回退到 `sit`；
- `fall` / `impact` / `recover` 回退到 `reaction`。

### `son-pet` 新增素材

- `drag`：复用现有 6 帧 `walk` 爬行。
- `climb`：6 帧，两人沿不可见侧边向上攀爬。
- `perch`：4 帧，两人坐在不可见顶边，腿自然垂下。
- `hang`：4 帧，两人双手抓住不可见下边缘，身体悬空。
- `fall`：4 帧，自然失去支撑并向下坠落。
- `impact`：4 帧，落地摔坐，不夸张变形。
- `pat-butt`：6 帧，起身、拍拍屁股并恢复正面跪姿。

所有帧必须保持两位人物的脸型、五官、发型、年龄、体型和服装一致。窗口、边线、文字和道具不得烘焙进素材。

处理器继续执行透明背景、安全间距、独立碎片、绿边、统一视觉体量、重心和画布校验，并增加互动锚点校验。

## IPC 与安全

预加载层仅暴露最小接口：

- 上报当前帧可见边距；
- 上报拖动开始、移动和结束；
- 接收互动状态更新。

所有 IPC 继续验证发送者为桌宠主渲染页。窗口探测结果只在主进程使用，不向页面暴露其他应用标题、进程路径或窗口内容。

不截图、不读取窗口内容、不保存其他应用信息。仅使用窗口 ID、层级和矩形边界。

## 错误处理

- `get-windows` 加载或调用失败：记录警告并禁用窗口附着，本次拖动正常结束。
- 候选窗口在松手与附着之间消失：进入坠落恢复流程。
- 候选边界无效：忽略该候选，继续寻找下一窗口。
- 附着轮询异常：清除轮询器并恢复普通跪姿或坠落。
- 动画缺失：使用标准动作回退。
- alpha 可见范围暂不可用：暂时使用保守的旧矩形限制，图片加载完成后更新。
- 应用退出：清理附着、坠落、漫游和行为计时器。
