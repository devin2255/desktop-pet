# 侧边常驻与合影争后排互动设计

## 目标

完成两项行为调整：

1. 宠物被拖到普通窗口左侧或右侧后，保持现有侧边趴伏姿态，不再等待 3 秒并自动爬到窗口顶部。
2. “小美小甜”的“合个影”功能复用现有 `selfie` 动画，通过连续对白表现两人争着站后排、因为后排显脸小的趣味互动。

## 侧边常驻行为

改动位于通用窗口互动控制器。宠物在目标窗口左侧或右侧松手后，继续使用资源包 `interactionActions.climb` 指定的动作和锚点，但状态含义调整为侧边常驻，不启动等待计时器，也不执行向顶部的位置动画。

侧边常驻期间：

- 目标窗口移动或改变尺寸时，宠物继续按现有附着机制跟随。
- 宠物保持朝向窗口内部。
- 用户重新拖动宠物时立即解除附着。
- 目标窗口消失或不再有效时，沿用现有脱离与下落处理。
- 顶部停留、底边悬挂以及其他桌宠行为不受影响。

该行为属于通用播放器能力，不在单个宠物资源包中增加专属分支。

## 合影争后排互动

不新增或重绘图片。将“小美小甜”资源包中的“合个影”菜单项从单一动作改为资源包序列，序列重复使用现有 `selfie` 动画，并依次显示：

1. “我站后面！”
2. “不行，后面显脸小！”
3. “那一起往后挤～”

每段自动推进，不要求用户额外点击。最后切回 `idle`，恢复随机行为调度。角色对白和节奏只存在于 `pet.json`，通用播放器只负责执行已有序列机制。

## 数据与兼容性

- 不改变 `.petpack` 的 `schemaVersion`。
- 使用当前已经支持的 `sequences` 和 `contextMenuActions.sequence` 字段。
- 其他宠物仍可使用单一 `action` 形式的菜单动作。
- 不删除现有 `selfie` 动画，避免资源路径和既有素材失效。

## 测试与验收

遵循测试先行：

1. 先修改窗口互动测试，断言侧边释放后保持侧边状态，不安排 3000 毫秒计时器、不启动爬升位移动画，也不切换到顶部停留状态；确认测试因旧行为而失败。
2. 再修改控制器，以最小改动令测试通过，并运行完整窗口互动测试。
3. 先扩展“小美小甜”资源包测试，断言“合个影”引用序列、序列包含三段复用 `selfie` 的对白和最终 `idle`；确认测试因旧配置而失败。
4. 更新解包目录中的 `pet.json`，重新生成 `xiaomei-xiaotian.petpack`，验证资源包并运行相关 JavaScript、Python 与回归测试。
5. 实际启动开发版，人工确认侧边常驻跟随和合影对白节奏；若当前环境无法可靠完成界面实测，在交付说明中明确列为未验证项。

## 非目标

- 不生成新的合影图片或动画帧。
- 不增加拍照保存、摄像头调用或系统截图能力。
- 不改变其他右键互动内容。
- 不为单只宠物在播放器中写死角色名称或对白。
